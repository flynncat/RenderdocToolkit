# Release Notes — 2026-05-12 ~ 2026-05-14

主题：**支持任意版本 / 魔改 RenderDoc 抓帧的端到端分析与对比**

本次发布跨越 3 个工作日 9 个提交（`5d2c9bb` → `6a2d79c`），围绕同一条主线：让工具能够处理"非默认 RenderDoc 版本（包括用户自行魔改的 RenderDoc 编译版本）抓出来的 `.rdc` 文件"，而不只是公版 v1.41。最终交付的能力是：

- 任务级（per-task）选择 RenderDoc 目录，性能 / 性能 Diff 两个 Tab 各自独立
- 抓帧文件格式自动识别，公版 Python API 不兼容时自动走 XML 回退分析路径
- 在自定义 RenderDoc 下也能拿到 GPU 耗时（近似）、指令数、覆盖率、绑定纹理、贴图带宽风险等关键性能指标
- 通过 `qrenderdoc.exe --python` 后端，绕过 Python ABI 不兼容，拿到 **真实 GPU 回放出的 RT / 绑定纹理 PNG**
- UE 移动端常见的 streaming 占位符纹理（capture 里只有 16 字节 ASTC 块）能被识别并展示真实像素或占位徽章
- 整个过程不需要修改用户的 custom RenderDoc 源码，也不需要远程协议（避免 v1.36/v1.41 版本严格校验）

---

## 1. 新增能力

### 1.1 任务级 RenderDoc 目录选择（`5d2c9bb`）
- 性能 / 性能 Diff Tab 各自新增 `RenderDoc 目录` 字段，可针对单次任务覆盖全局环境配置
- 路径解析链：`任务级 override` → 全局 `RENDERDOC_PYTHON_PATH` → 包内 bundled `renderdoccmd` → 系统 `PATH`
- 新增 `app/services/renderdoc_runtime_resolver.py` 作为统一解析入口，所有路径决策在一个文件内完成
- Job 元数据中记录最终解析到的 `renderdoc_dir / renderdoc_python_path / renderdoc_source`，便于排查
- 子进程隔离：每次绘制预览都在独立 subprocess 中进行，避免不同版本 RenderDoc 的 Python 模块缓存互相污染

### 1.2 XML 回退分析路径（`0f81355` → `ce6b841`）
当抓帧使用与公版 Python 模块不兼容的文件格式（如 v1.36 的 `CODR/RDOC` 魔数）时，工具自动启用纯 XML 回退分析：

- 文件魔数识别 → `renderdoccmd convert -c zip.xml` 产出 XML + 同名 `.zip`（原始资源缓冲）
- 解析 GL 状态：纹理目录（`glTexStorage2D` / `glTexImage2D`）、绑定纹理（`glActiveTexture` + `glBindTexture`）、viewport（`glViewport`）、当前 program（`glUseProgram`）
- 性能指标重建：
  - GPU 耗时近似 ← `renderdoccmd convert -c chrome.json` 的 CPU API 时间戳
  - 指令数估算 ← 从 `glShaderSource` 提取 GLSL 后做加权 ALU/纹理指令计数
  - 屏幕覆盖率 ← 以最大 viewport 为屏幕基准换算
- 每行 Draw 包含：`texture_count`、`texture_total_mb`、`texture_bandwidth_risk`、`target_width/height`、`shader_program ID`
- Capture 整体缩略图 ← `renderdoccmd thumb` 导出，前端在性能页头部展示
- 处理中文路径的编码问题：`renderdoccmd` 输出走 bytes 通道避免 GBK 解码失败；输出文件名强制 ASCII

### 1.3 qrenderdoc `--python` 真实回放后端（`6a2d79c`）
这一版本是整套改造的"王冠"。即使用户的 RenderDoc 是 v1.36 / Python 3.6（与工具的 Python 3.13 ABI 不兼容），我们仍然可以拿到 **真实 GPU 像素**：

- 新增 `app/services/replay_backend.py`：`QRenderdocScriptBackend` 抽象，通过 `subprocess` 启动用户的 `qrenderdoc.exe --python <worker>`，由 qrenderdoc 内嵌的 Python 3.6 解释器加载与该版本匹配的 `renderdoc` 模块
- 新增 `external_tools/renderdoccmp/qr_replay_worker.py`：worker 脚本，在 qrenderdoc 进程内做 `OpenCapture` → `SetFrameEvent(eid)` → 通过 `action.outputs[]` 取 per-draw RT、通过 `GetDescriptorAccess() + GetDescriptors()` 取绑定纹理 → `SaveTexture(rid, png)` → 写 `manifest.json` → `sys.exit(0)` 让 qrenderdoc 不弹 UI
- 性能 Tab：XML 分析完成后自动跑后端，top-N 热点 draws 拿真实 RT + 绑定纹理 PNG；manifest 同时输出 `eventId` 与 `events[-1].chunkIndex`，所以 XML 行的 chunkIndex-EID 能与 replay-API 的 eventId 对齐
- cmp Tab：在调 `rdc_compare_ultimate.py` 之前对两份抓帧各跑一次 cmp-mode（跳过 per-draw、只 dump 全局纹理 roster，128 张/抓帧封顶）

### 1.4 前端预览来源标识
四种 preview kind 用边框颜色区分：

| Kind | 边框 | 含义 |
|---|---|---|
| `rt_replay` | 绿色实线 | qrenderdoc 真实 GPU 回放出的 RT |
| `tex_replay` | 绿色虚线 | 该 draw 不写颜色 RT（shadow map / depth-only），改展示首张绑定纹理 |
| `wireframe_overlay` | 蓝色实线 | 公版 Python 直连回放生成的线框 |
| `texture` | 橙色实线 | 无可用回放后端时，XML 回退从 `capture.zip` 解码出的绑定纹理 |

性能页头部新增徽章：`XML 分析 + qrenderdoc 真实回放（N draw 已升级）`。

### 1.5 UE Streaming 占位符纹理可视化（`91bf69e`）
UE 移动端的 Initial Contents 经常只存了最低 mip 的单个 16 字节 ASTC 块（真实数据是运行时流式加载，从未进 `.rdc`）。以前这些纹理在 cmp 报告里全是 "No Preview"，现在：

- 解码可用 block，nearest-neighbour 上采样让代表色可见
- HTML 报告区分三态：
  - **完整资产**：正常预览
  - **占位符**：预览 + 虚线琥珀色边框 + "占位符" 徽章
  - **真无数据**：`No Preview` 单元格 + 提示文字（depth target / EGLImage external 等）

## 2. 修复

### 2.1 子进程崩溃保护（`ff309e0`）
- cmp 脚本不再 `runpy.run_path` 同进程运行，改 `multiprocessing.Process` 子进程隔离，45 分钟 wall-clock 上限
- 子进程崩溃（OOM、astcenc/malioc segfault 等）不再连带杀死 web 服务和桌面窗口
- `stdout/stderr` 实时落盘到 `cmp_run_log.txt`，即使崩溃也保留部分输出可供排查

### 2.2 CMD 窗口隐藏（`ff309e0`）
- `rdc_compare_ultimate.py` 内所有 `subprocess.run`（astcenc、`renderdoccmd convert`、malioc）都加上 `CREATE_NO_WINDOW` + `STARTUPINFO.wShowWindow=SW_HIDE`
- `app/services/subprocess_utils.py` 同步强化双重防御
- 不再有窗口抢焦点打断用户输入

### 2.3 FastAPI 事件循环不阻塞（`ff309e0`）
- 长时间 cmp 调用包进 `run_in_threadpool`，多分钟 cmp 跑批期间 `/api/health`、Job 列表等接口继续响应

### 2.4 cmp 纹理预览全 "No Preview"（`4666499`）
- 修复 GL 纹理提取器只识别 `glCompressedTexSubImage2D.pixels` 的局限，现在也识别 `Internal::Initial Contents.SubresourceContents`
- 验收：F:\snap\apple-pudding-outside.rdc 上 ASTC 纹理缩略图数量从 0 → 456 张

### 2.5 前端 `inputs is not defined` + tkinter 主线程崩溃（`caee035`）
- `renderPerfSummary` 补 `const inputs = metadata.inputs || {}`
- DesktopBridge 文件 / 目录选择对话框从 `tkinter` 切到 `pywebview` `window.create_file_dialog()`，根除 `main thread is not in main loop` 错误

### 2.6 PyInstaller 构建脚本误报错误
- `build_portable.ps1` 之前因 PyInstaller 的 INFO 输出走 stderr 被 PowerShell `$ErrorActionPreference=Stop` 误报为错误中止
- 现在临时切到 `Continue`，靠 `$LASTEXITCODE` 判断真实失败

## 3. 关键技术决策

| 决策 | 理由 |
|---|---|
| 不修改用户的 custom RenderDoc 源码 | 用户明确要求；保持其抓帧/调试环境不动 |
| 不走 RenderDoc 远程服务器协议（Plan B2） | v1.36 client/server 严格校验版本号，公版 v1.41 客户端无法与用户 v1.36 服务器通信 |
| 选择 `qrenderdoc.exe --python` 头跑模式（Plan B1） | 借用 qrenderdoc 自带的 Python 解释器，自动加载匹配 ABI 的 `renderdoc` 模块；`sys.exit(0)` 让 GUI 不弹出 |
| 每次调用独立 subprocess + 隐藏窗口 | 崩溃隔离；用户输入不被 CMD 窗口打断 |
| 中文路径全程 UTF-8 + env var | 通过 `QR_JOB_JSON_PATH` 传绝对路径，避免 PowerShell↔Python 字符串编码歧义 |
| Manifest 同时输出 eventId 与 chunkIndex | XML 分析按 chunkIndex 编号 draw，replay API 按 eventId 编号；两个 ID 空间不同必须双向输出才能对齐 |

## 6. 升级提示

- 首次使用魔改 RenderDoc 时，在性能 / 性能 Diff 页填入 RenderDoc 安装目录（包含 `qrenderdoc.exe` 与 `renderdoccmd.exe` 的目录）即可
- 性能 Tab 没有 qrenderdoc.exe 时仍可工作，但会回退到 XML+绑定纹理预览，不会有 RT 真实像素
- cmp Tab 跑大型 UE 抓帧时长度可能 10-30 分钟，过程中可以正常使用其他 Tab；如果中途崩溃，子进程会被回收且服务保持运行，HTML 报告至少包含到崩溃前已写入的部分
- 若想绕过 qrenderdoc 后端只走纯 XML 分析，把 RenderDoc 目录字段留空即可

## 7. 已知限制 / 后续可改进点

- qrenderdoc 后端 cmp-mode 当前 `max_extra_textures=1024` 封顶；超大场景（>2000 纹理）只能拿到子集
- 部分 streaming 纹理只在非 `(0,0)` 偏移处上传的小 sub-image，无法 tile-reassembly 还原全图；这些仍会显示占位符徽章
- Vulkan / D3D 抓帧的 per-draw 绑定纹理提取在 worker 里走的是简化路径，复杂 descriptor 表可能漏取（GL 已完整支持）
- chrome.json 时间戳是 CPU API 时间，不是真实 GPU 时间，作"相对热度排序"足够，绝对值有偏差
